## Boundaries and current login

Authentication is Supabase Auth. `/admin/login` calls `signInWithOtp` with `shouldCreateUser: false` after a server-side eligibility lookup. An ineligible address gets the same visible sent state and no Auth call. The callback is exactly `/auth/callback`; `exchangeCodeForSession` uses the PKCE verifier stored by the SSR client in the browser that requested the link. The server reconciles membership and returns either `/admin` or a generic login error. Logout calls `supabase.auth.signOut`. Missing/inactive membership is denied, regardless of a valid Auth session.

Authorization remains the existing `admin_profiles`/RBAC model. `owner`, `admin`, `viewer`, invitation acceptance, audited owner transfer, and the first-owner bootstrap RPC are unchanged. A valid email token alone gives no Admin access. A new-user invitation uses `inviteUserByEmail` and `/auth/confirm?token_hash=…&type=invite`; `verifyOtp` runs server-side, then reconciles the current pending invitation. Existing confirmed users use normal magic-link login.

## Delivery architecture

Supabase Auth → HTTPS Send Email Hook → `supabase/functions/send-admin-auth-email` → React Email HTML + text → Resend `POST https://api.resend.com/emails`.

Supabase creates and verifies all Auth tokens. The function does not generate tokens or expose a generic email endpoint. It verifies the Standard Webhooks signature and timestamp before parsing the payload. Only `magiclink` and `invite` are accepted. The signed recipient comes from `user.email`; subject and template are selected by a closed type map. `token_hash` is used only for the appropriate Supabase verify URL or the existing server invite confirmation route. The hook's `redirect_to` must have an exact configured origin and the exact `/auth/callback` or `/auth/confirm` path, with no query, fragment, userinfo, or wildcard origin. Default allowed origin is `https://pozanuta.pl`; local/Preview origins must be explicitly configured for a hook-enabled environment. Supabase's own Auth Redirect URLs must separately allow each actual redirect.

The production sender defaults to `Poza Nutą <no-reply@auth.pozanuta.pl>` and can be overridden by `AUTH_EMAIL_FROM` for a verified sending domain. Configure `RESEND_API_KEY`, `SEND_EMAIL_HOOK_SECRET` (`v1,whsec_…` generated by the Supabase Auth Hooks UI), and optionally `AUTH_EMAIL_FROM` and `AUTH_EMAIL_ALLOWED_ORIGINS` as **Supabase Edge Function secrets only**. `SUPABASE_URL` is supplied by the Edge runtime. None belongs in `NEXT_PUBLIC_*` or Vercel. The application still needs `NEXT_PUBLIC_SITE_URL=https://pozanuta.pl`, its existing Supabase URL/publishable key/secret key, and temporary `BOOTSTRAP_OWNER_EMAIL` in Vercel server configuration; no Resend key belongs there.

The template is Polish, text-led, and independent of remote images/CSS. It has a descriptive CTA, visible raw-link fallback, one-time/limited-validity wording without a hard-coded duration, and a separate plain-text body. No UTM, marketing link, or instrumentation is added. On 2026-09-29 the verified domain's Configuration tab offered **“Enable tracking metrics”** and opened a **new tracking subdomain** setup; no tracking domain existed. Resend documents both domain-level options as disabled by default. The delivered message's provider HTML preview contained no `<img>` or external asset tag and kept the direct Supabase Auth link without a tracking redirect. Together these observations support **Open Tracking OFF / Click Tracking OFF** for this delivery; no tracking settings were changed.

Password recovery and email change are not part of the present passwordless Admin flow. Do not enable flows that emit those messages until templates and security handling are added.
