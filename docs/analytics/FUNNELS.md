# Consented session funnels

The server-controlled `FUNNELS` contract in `src/lib/analytics/funnel-contract.ts` names two stable presets: `contact_intent` (`contact_view` → `contact_click`) and `tracked_entry_to_contact` (`tracking_entry` → `contact_view` → `contact_click`). The latter measures a same-session path from an owned `/r` entry; it does not attribute conversions to a campaign. Display labels are not identities. Requests accept only the preset key, canonical admin date range and closed Reporting Scope.

`public.analytics_funnel_v1` is the sole read model. It reads accepted consented rows in `analytics_events_v2` with `analytics_consent = true` and current `schema_version = 1`. It never reads `analytics_cookieless_events`, quality exceptions, Realtime aggregates or visitor IDs. Duplicate ingest returns without a second primary event row; rejected and filtered attempts have no primary event row. A consented event has a required session FK and a unique `(session_id, session_sequence)` assigned by atomic ingest. The HMAC-signed browser session is created after consent and refreshed for approximately 30 minutes of inactivity; a later session linked by visitor ID stays separate here.

Every event used for progression must pass `analytics_reporting_eligible_v1` **before** the sequence is built. Business means `production` + `external`; Diagnostic includes accepted stored classifications. `occurred_at` is the server-side event time. The event window is `[fromDate at 00:00 Europe/Warsaw, toDateExclusive at 00:00 Europe/Warsaw)`. Both first and later steps must fall within it. This is not a cohort-entry window, and completion after the end is not counted. Custom windows are limited to 366 days.

For each session and preset the query picks the first qualifying step 1 event, then the earliest qualifying next event whose `session_sequence` is greater and `occurred_at` is no earlier. It repeats for each step. Equal timestamps progress only when the real per-session sequence increases. An event with a later timestamp but an earlier sequence does not progress. Intermediate events are allowed. A repeated step never starts a second attempt and each session contributes at most once to each step. The report does not stitch sessions, devices, or visitors.

`entrants` is the number of unique consented sessions completing step 1. Each next `sessions` count is the number completing all ordered steps through that point. `conversionRate = 100 × current / previous`, `dropOff = previous − current`, `dropOffRate = 100 × dropOff / previous`, and `completionRate = 100 × final / entrants`. Percentage fields are `null` when their denominator is zero. `eligibleSessions` counts unique accepted consented sessions in the selected event window and scope, regardless of whether they entered this preset; it distinguishes an empty population from a funnel with no entrants. Rates are rounded to one decimal place.

The RPC is `security invoker`, uses fixed SQL and a closed key map, validates dates and scope, has EXECUTE granted only to `service_role`, and relies on existing service-role SELECT and RLS on `analytics_events_v2`. The admin page checks active membership on each request; `viewer` can read and cannot mutate. No public tracking, identity, cookie, schema table or anonymous/authenticated privilege was added.
