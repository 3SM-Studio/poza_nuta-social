# Consented page paths

`/admin/paths` reports ordered page views within one consented session. The typed node is `{ type: "page", path: canonicalStoredPath }`. `page_view` is the only qualifying event. Contact events, redirect events and `hub_resumed` retain their own taxonomy and are not nodes in this foundation. The client maps accepted public routes to canonical pathnames; `sanitizePagePath` uses the public-route allowlist, so query strings and fragments are not stored as page identity. The SQL reads `analytics_events_v2.path` unchanged, including historical values such as `/privacy`. It does not regroup slugs or use page titles.

The source is accepted rows of `analytics_events_v2` with `analytics_consent = true`, `schema_version = 1`, and `event_name = 'page_view'`. Rejected, duplicate and filtered attempts have no additional primary row. `analytics_cookieless_events`, quality observations, visitor IDs and raw event payloads are not read. A signed session is created after consent and refreshed for about 30 minutes of inactivity; distinct session IDs stay distinct even if visitor IDs match. There is no cookie or tracking addition.

The report uses the canonical admin event window `[fromDate 00:00 Europe/Warsaw, toDateExclusive 00:00 Europe/Warsaw)`, at most 366 days. It is **not** an entry cohort. `analytics_reporting_eligible_v1` filters each event before sequence formation. Business is production/external; Diagnostic includes accepted stored classifications. Within a session the order is `occurred_at, session_sequence`, matching Funnels. The sequence is unique per session; equal timestamps use `session_sequence`, never event UUID. Consecutive repeats remain distinct.

`pathSessions` is the number of unique consented sessions with at least one qualifying page view in the selected window and scope. `entries` counts the first **observed in-window** node per session, not a proven landing page. `shortPaths` counts one prefix of at most three page nodes per session. Detail uses the first occurrence of the selected page per session and counts its immediately preceding and following qualifying page. Intermediate non-page events are ignored. Each session contributes at most once to each distribution. `selectedSessions` is the detail denominator. `noNextInRange` and `noPreviousInRange` count selected sessions without that neighbor inside the window; `noNextInRange` is **not** an exit estimate. A later page outside the window does not appear as next. Share is row sessions divided by `pathSessions` for overview and by `selectedSessions` for detail; absent denominator yields no percentage.

The server-owned `analytics_paths_v1` RPC returns top 10 entries, top 10 prefixes, and top 10 each for next/previous, with a fixed depth of three. Its only node input is a bounded stored path value (maximum 160 bytes and a closed path shape). SQL is static and parameterized. The function is `security invoker`, owned by `postgres`, and executable only by `service_role`. The existing primary event RLS and table grants remain unchanged; anon and authenticated gain no read or EXECUTE rights. The Next.js route requires active admin membership on every request and allows viewers to read without mutation.

This page-only read model intentionally excludes cookieless paths and cannot describe the behavior of all traffic. It does not claim true session exit, cross-session behavior or campaign attribution.

## Local query-plan check

`scripts/paths-explain.sql` inserts 3,000 synthetic sessions and 9,000 page views inside one transaction, analyzes the local table, runs `EXPLAIN (ANALYZE, BUFFERS)` for entry, next, previous and short-path aggregations at 7 and 30 days, then rolls back. On this local dataset the 7-day plans used the existing `analytics_events_v2_quality_range_idx` and took 1.8, 2.6, 2.3 and 2.9 ms respectively. The 30-day plans chose a sequential scan of the small local table and took 6.9, 14.0, 9.4 and 13.2 ms. These are local observations, not production forecasts. The plans did not establish a need for another index; the transaction left no synthetic rows.
